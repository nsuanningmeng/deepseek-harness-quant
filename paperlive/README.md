# 当前行情驱动的实时模拟账户

从账户创建时刻开始前向记账，不导入历史成交或历史收益。`paperlive` 不导入券商 SDK，也没有实盘提交入口。

在项目根目录运行：

```sh
.venv/bin/python -m paperlive run
```

`launcher.py` 会启动行情验收后台、网页、研究更新与分钟下载服务。网页为 `http://127.0.0.1:8787/paperlive`。账户、行情状态、委托、成交及 AI 计划保存在配置的 `runtime_dir`；停止进程后重新启动会继续同一账户。

配置是 `config/paperlive.yaml`，模板为同名 `.example`。本机按用户要求使用 50,000 元虚拟资金，运行目录为 `runtime/paperlive-50000/`；旧的 100 万元空账户保留在原目录。当前策略模式是 AI。账户建立后，资金、费用和市场执行规则被冻结。用户明确授权的单股、总仓位、单笔金额及回撤触发线可以在闭市、后台停止、暂停标记存在且没有未完成委托时，通过 `paperlive.risk_policy` 审计迁移；保留同一账户和全部历史，旧规则进程不能继续写账本。其他执行规则变更仍需新的运行目录。AI 模型从已配置的本地 Harness 设置读取，凭据仅从本机凭据文件读取，请求被限制在 `ai.allowed_origin` 指定的 HTTPS 中转域名，模型不能调用工具或修改账本。

## 条件自动启动

用户授权的自动启用通过 `activation` 配置和持久验收状态控制。行情后台可以在等待期间运行，但研究产物、全部分析步骤、当前沪深300身份、完整历史分钟窗口、官方交易日历、新鲜报价、实际涨跌停价、AI真实JSON验证和账户对账必须同时通过，且处于连续竞价时段，才能解除程序自己建立的等待标记。未通过项显示在模拟盘页面；历史样本下载完成不代表实时行情新鲜。

启动后仍持续核验，数据缺失或过期时阻止新的AI计划和买入。人工新建或改动 `STOP` 优先于自动启用，取消自动解除资格。只打开页面或启动进程不会制造成交，休市不产生交易计划。

## 行情与运行时段

- 本机明确选择 `market.provider: tencent_tushare`：腾讯提供公开盘口，Tushare 官方提供证券资料 `stock_basic`、日历 `trade_cal`、成分 `index_weight` 和实际涨跌停价 `stk_limit`。此组合不调用单独付费的 `rt_k`；原 `tushare` 模式仍保留供明确选择。
- 沪深300池使用 `index_weight` 最近一期有效的完整300成分快照，再排除不支持证券、ST和上市天数不足的标的。该接口是月度权重快照，状态记录实际 `effective_date`；不能把月度资料称为每日实时成分。超过配置允许时效或成分资料不完整时停止新买入，离池持仓继续查证券资料及行情。
- 腾讯快照保留供应商实际时间，累计量与盘口量由手转换为股；前收盘价和涨跌停边界与当日官方资料交叉核对。原 Tushare 模式使用 `rt_k` 的 `trade_time` 与股数单位。缺字段、陈旧、未来或乱序报价不参与撮合，缺当日实际涨跌停价时不推导替代。
- 仅在确认的交易日及配置的连续竞价时段撮合，默认 09:30–11:30、13:00–14:57。午休、集合竞价和休市不撮合；闭市也不请求 AI 交易计划。
- 盘中默认每10秒读取行情，AI最多每30分钟生成一轮计划，每轮至多3笔委托。没有足够行情或依据时可以保持现金，不保证会产生交易。

## 模拟成交口径

委托先冻结现金或可卖股票，只能由委托接收后到达的新鲜报价触发成交。买单参考卖一、卖单参考买一，计滑点及费用，并受可见盘口数量的配置比例限制；同一批盘口容量共享，不使用未来全天成交量。支持部分成交、撤单解冻、T+1批次和恢复幂等，收盘撤余。公开盘口不能验证真实队列位置或全部停牌状态，因此这是报价驱动的简化纸面撮合，不能作为真实成交保证。

持仓遇到除权标记或前收盘价无法核对时阻断相关执行，并标记估值不完整。行情缺失或不完整时保留最后已知估值及其时间，不能把它当作最新可成交价。

配置的 `risk.kill_switch_file` 暂停新增委托并撤销未完成委托。开启条件自动启用时，人工暂停会取消自动解除资格；不能仅删除暂停文件就绕过验收。长时间运行需要本机联网、保持唤醒和进程存活。

macOS 的本机登录恢复由 `config/local_services.yaml` 管理，覆盖网页、AI控制、模拟观察、研究更新和分钟维护。用户登录后恢复服务，异常退出后按配置等待重试；恢复服务仍须通过原有数据验收，不会删除暂停文件或重建账户。查看状态运行 `.venv/bin/python -m data.local_services status`；停止并移除登录恢复运行 `.venv/bin/python -m data.local_services remove`。可加 `--service web` 等指定单项。启动诊断日志放在配置指定的 `~/Library/Logs/deepseek-quant/`，程序运行日志仍保存在项目 `runtime/`；不修改 macOS 隐私权限。关机和断网期间无法采集实时行情，恢复后不会补造错过的成交。

在网页 `/data-settings` 填写自己的 Tushare Token 并点击“保存到本机”，再手动验证权限。Token 保存在被 Git 忽略的独立文件、权限0600，不回显、不写浏览器存储；只发送至固定的 Tushare 官方 HTTPS。凭据变更会使旧验证失效。`TUSHARE_TOKEN` 环境变量也可作为无本地文件时的来源。

纯 Tushare 模式下，基础数据积分权限与 `rt_k` 的“A股日线RT”独立授权分别验证。混合模式只检查所需基础接口，不会把没有 `rt_k` 权限误报为腾讯行情不可用。两种模式都不能以保存 Token 或基础接口成功代替盘中新鲜度验收。

网页请求失败时不回退旧缓存；即使网页服务仍在线，行情进程心跳过期也会明确显示等待恢复并停用委托入口。盘中与休市分别按实际刷新周期及配置宽限判断，临近开盘不会沿用整段休市容忍时间。

## 验证

```sh
.venv/bin/python validation/run_isolated_tests.py
```

隔离测试会阻止测试代码访问正式数据库及正式服务端口。测试包括现金/股票冻结、T+1、费用与对账、部分成交、报价时间与容量、重复及并发幂等、真实日历时段、AI输出与目的域限制。真实闭市循环另行验证行情覆盖和账户状态；下一交易时段的实际在线计划与成交仍需继续观察，闭市测试不会制造成交。

双角色交易决策由 `config/paperlive_council.yaml` 配置，角色定义与控制页共享 `config/niu_personas.yaml`。冯柳风格角色基于同一份行情、账户、已核验研究和当前风控提出草案；方法论角色逐项批准或否决，不能增加订单或修改量价。程序只将获批原提案送入账本风控，任何缺失、超时、配置变化、复核不完整或证据不符都会停止该轮提交。它们是 AI 风格模拟，并非本人或其真实交易信号。

启用前需完成一次包含两角色请求的真实空输入验证，证明两个角色及 JSON 流程可用；这类验证独立保存为 `council-verification.json`，不会生成委托，也不会冒充盘中报告。盘中实际分析、逐项意见、失败和过期原因保存于账户的 `plans/` 并显示在模拟盘页面。风控页仅在当前心跳及账本绑定一致时显示“已核对生效”。回撤触发线是停止保护条件，不是最大亏损保证；仍受 T+1、跳空及无法成交等限制。


协议 7 支持整轮共享一次格式重试。仅当 HTTP 200 正常结束、响应正文无法解析为 JSON 时重试对应角色，重试继续使用同一输入与结构，生成新请求编号并关联首个失败编号。单角色请求累计 60 秒、双角色共享 80 秒、委托计划有效期 90 秒。重试额度由 `config/paperlive_council.yaml` 中的 `max_format_retries` 配置。

本机状态可从 `/api/system_live`、`/api/live/minute` 和 `/api/paperlive/state` 查看。读取模拟盘状态 API 可能写入估值曲线。只读审计可检查运行目录内的 `state.json`、`plans/` 与以 SQLite `mode=ro` 打开的账本。收盘后实时报价会失效，报告收盘权益时应使用已核验的当日收盘价。
