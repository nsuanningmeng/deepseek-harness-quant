# 分钟数据接入说明

本机沪深300历史5分钟数据使用独立后台下载；1分钟或期货分钟文件仍可按下文手动导入。两种频率不能互相冒充。

## 当前沪深300历史5分钟

`config/research_minute_source.yaml` 明确选择来源，统一状态入口是 `data.minute_readiness.public_status()`。当前以 BaoStock 免费公开历史数据为主，写入独立 `data/cache/minute_baostock.db`；日线交叉核验发现异常时，可以用新浪真实5分钟数据整日修补。行级来源、替换前数据及原始响应摘要均保留，新浪行不会标成 BaoStock。已下载的 Tushare 分钟库仍保留在原 `minute.db`。

每只股票按实际日线交易日核验完整的48个5分钟时段，逐日检查开收盘价，以及单位换算后的成交量和成交额。成功入库与下载凭证在同一事务提交，重启会核验断点。下载范围、来源、覆盖数、目标日期和质量差异在状态中保留；只有全部股票和当前日期通过校验才标为就绪。

日历中的缺失交易日须有 Tushare 官方 `suspend_d` 全天停牌记录支持；仅仅没有日线不能推断为停牌。原始停复牌记录、响应摘要及同日停复牌并存情况会保留，不补造零成交分钟线。

BaoStock 成交额交叉核验保留0.10元容差；新浪修补源采用配置中的绝对与相对精度界，当前为 `max(0.10元, 日成交额×1e-8)`。实际金额差异和容差逐日记录，不宣称跨源逐分金额完全相同；成交量、开收盘价、时段与日期完整性的要求不因换源放宽。大额缺量或错误收盘价不会以“误差”放行。

下载完成后，研究日期前移会建立新的固定窗口任务，只请求缺少的尾部日期，并复核复用数据的原有凭证。页面读取先返回“正在核验”，本轮全部股票的凭证、行数、内容摘要及日线交叉检查通过后才显示就绪；配置或数据修改会使旧核验失效。

旧日期和旧成分股的数据继续保留。页面、数据库健康检查与独立验收只按本轮固定日期和股票池计数，另外列出 `total_cache_rows`；全库缓存行数不能代替本轮覆盖数。核心更新持有写锁时，分钟维护与深度核验等待，不改旧下载凭证。短暂数据库读锁失败会在冷却后重试，不会永久保留为缺失状态。

两个供应商的日内最高、最低价可能不一致，保留各自原始值与差异记录，不猜测差异原因，也不把历史5分钟数据用于精细盘口撮合或集合竞价。实时模拟使用独立的带源时间盘口。

查看下载状态：

```sh
.venv/bin/python -m data.research_minute_baostock status
```

原 Tushare 小时额度下载器保留独立任务和请求间隔保护；切换来源需明确修改来源配置，不会同时混写。

## 一、外部文件使用流程

1. 将分钟数据放入 `data/minute/download/`（任意格式、嵌套目录均可）
2. 运行 `python data/ingest_minute.py --scan`（或接入每日自动调度）——自动解析（列名/编码/压缩包格式自适应）并入库 `minute.db`
3. `python data/ingest_minute.py --status` 查看入库进度

## 二、入库规范

```
minute.db
├── minute_1m(code TEXT, trade_time TEXT, open/high/low/close REAL,
│             volume REAL, amount REAL, source TEXT,
│             PRIMARY KEY(code, trade_time))        -- 主键防重复
└── bar_meta(source, code, start_time, end_time, rows, updated_at)
```

- **source**：`a_share`（带 .SZ/.SH 后缀） / `futures`（品种+合约，如 rb2610）
- **格式自适应**：自动探测列名（time/trade_time、vol/volume、ts_code/symbol/code 等），支持 .csv/.txt/.csv.gz；单股票文件无 code 列时用文件名推断
- **重复入库安全**：INSERT OR REPLACE，重跑不产生重复
