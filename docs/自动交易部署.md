# A 股自动模拟交易：安装、调度与恢复

第二阶段已补历史预热/恢复、BaoStock受限真实行情和QMT接口代码。数据源选择、只读终端配置及未完成实连验收项请先看[真实行情与QMT接入](真实行情与QMT接入.md)。

## 安装与离线验收

在仓库根目录执行，支持 Python 3.10+。只安装模拟模块依赖即可，不必启动 HARNESS。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-autotrade.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_autotrade*.py" -v
.\.venv\Scripts\python.exe -m autotrade demo
```

Linux将Python路径换为`.venv/bin/python`。演示是27个合成交易日、6个测试证券标识，不包含真实行情。
演示将调仓周期设为2日、Top3，以覆盖买卖/部分成交；正式模板仍为40日、Top10。
重复同一演示目录不会重复成交。修改策略、风险、成本或股票池后请用新的运行目录，旧账户配置指纹不可静默替换。

产物位于`runtime/autotrade-demo/`：

| 文件 | 用途 |
| --- | --- |
| demo-config.yaml / demo-summary.json | 可重放配置、完整演示结果 |
| market/YYYY-MM-DD.json | 未复权、股单位行情及证券状态 |
| paper.sqlite3 | 配置/行情摘要、计划、订单、成交、FIFO批次、现金、估值、审计 |
| reports/YYYY-MM-DD.json | 每日状态、资产、持仓、订单与对账 |
| events.jsonl / health.json | 结构化事件与最近周期健康状态 |
| scheduler.json | 调度进程心跳/错误，运行调度后生成 |

```powershell
.\.venv\Scripts\python.exe -m autotrade --config runtime/autotrade-demo/demo-config.yaml status
```

`health`检查对账、紧急停止、周期/行情时效及调度错误，失败退出码1。历史演示的行情时效检查可能失败，这是预期；不能把历史重放当成当日健康数据。

## 配置真实行情（仍为模拟交易）

```powershell
Copy-Item config/autotrade.yaml.example config/autotrade.yaml
```

编辑本地配置：保持`mode: paper`、QMT的`enabled/live_trading_enabled/manual_authorization`为false、`read_only`为true；设置`data.provider: tushare`、用户自行选择的`data.universe`、运行目录、风险和成本参数。
默认模板股票池为空，不能在未配置时抓取全市场；不提供选股建议或预选真实证券名单。
以安全方式向运行进程设置`TUSHARE_TOKEN`环境变量，禁止将真实令牌写入配置、Git或任务命令行。

需要Tushare官方接口权限：

- [daily未复权日线](https://tushare.pro/document/2?doc_id=27)、[daily_basic换手率](https://tushare.pro/document/2?doc_id=32)
- [stk_limit当日上下限](https://tushare.pro/document/2?doc_id=183)、[stock_st风险警示](https://tushare.pro/document/2?doc_id=397)
- [trade_cal交易日历](https://tushare.pro/document/2?doc_id=26)、[stock_basic证券资料](https://tushare.pro/document/2?doc_id=25)
- [suspend_d按日停复牌](https://tushare.pro/document/2?doc_id=214)

新Tushare适配器直接使用官方HTTPS，不需要tushare/pandas依赖。支持2019年以来已结束交易日；当天15:30后可首次抓取，建议按默认16:30调度，接口尚未完整更新则失败并等待重试。
任何预期股票缺失/重复、接口无权限、日历不明、价格异常都不发布部分快照。
已封存快照重放无需联网。已有行情被修改会被摘要检查阻断，需要人工审计后另建运行目录重建，不能删摘要规避。

冷启动要求20个连续有效交易日，不会不足窗口即下单。第二阶段可用bootstrap下载历史并在调度时自动预热；历史ST/停牌/上下限按日核验，行业统一unknown，不能把当前元数据冒充历史事实。
Tushare令牌权限与生产吞吐仍需用户环境验收；无账号BaoStock真实数据的受限模拟路线已实际验证，限制见第二阶段说明。

## 日常运行和调度

```powershell
# 单个已结束交易日，日期必须与快照完全一致
.\.venv\Scripts\python.exe -m autotrade --config config/autotrade.yaml run --date YYYY-MM-DD
# 常驻：北京时间16:30起，每60秒检查；休市由明确日历判断
.\.venv\Scripts\python.exe -m autotrade --config config/autotrade.yaml schedule
# 给操作系统计划任务使用：执行一次调度判断，返回后退出
.\.venv\Scripts\python.exe -m autotrade --config config/autotrade.yaml schedule --once
.\.venv\Scripts\python.exe -m autotrade --config config/autotrade.yaml health
```

文件数据模式需要`market/calendar.json`：`{"start":"YYYY-MM-DD","end":"YYYY-MM-DD","sessions":["YYYY-MM-DD"]}`，由可靠交易所日历生成。不能把周一到周五当作完整交易日历；覆盖到期明确失败。
默认健康阈值为48小时，长假需根据可靠日历安排监控维护窗口或调整阈值；周期心跳不能替代行情时效。

Windows任务计划程序：程序指定虚拟环境Python绝对路径，参数为上面的`-m autotrade ... schedule --once`，起始目录为仓库根目录；交易执行使用独立低权限服务账号。
Linux可使用如下服务文件，修改路径/用户后由管理员安装；本任务不会擅自注册系统服务：

```ini
[Unit]
Description=A-share paper trading
After=network-online.target
[Service]
User=quant-paper
WorkingDirectory=/srv/deepseek-harness-quant
EnvironmentFile=/etc/quant-paper.env
ExecStart=/srv/deepseek-harness-quant/.venv/bin/python -m autotrade --config config/autotrade.yaml schedule
Restart=on-failure
RestartSec=30
NoNewPrivileges=true
[Install]
WantedBy=multi-user.target
```

配置、代码及账本由执行账号控制，HARNESS研究账号仅获单向导出的只读快照。不要让研究代理能修改文件、调用执行账号进程或读取未来券商凭据。

## 停止、异常恢复与回滚

- 创建配置中的`risk.kill_switch_file`（默认`runtime/autotrade/STOP`）阻止所有新订单；停止调度进程后备份整个运行目录。研究界面继续使用原路径，不影响旧账户。
- 单笔失败/部分成交是持久终态，重跑不再次下单；下一次调仓才重新计算差额。
- 进程崩溃可重新执行同一日。已提交成交保留，未提交事务回滚；原订单意图和ID保持不变。
- 跨日漏行情不会自动猜测。第二阶段可按明确日历补历史快照并顺序恢复模拟周期；缺权限/关键历史字段或超过补数上限时停止，不能用当前值填造过去。
- 对账失败、除权参考价变化、缺持仓行情需人工调查；不能删除订单、改现金或跳过检查来续跑。当前版本未实现红利/送转股入账。
- 改参数/股票池或升级不兼容账本时，备份旧目录并使用新目录重新验收。运行中的账本应停服务后备份，不能只复制一部分文件。
- 回滚代码：停止新增调度，保留运行目录，切回fork的`master`或revert该功能提交。原有研究/回测文件未被重写，不需迁移原数据。

## 后续实盘接入条件

1. 券商确认账户、板块适当性、QMT/XtQuant外部接口及程序化交易相关权限/报告要求。
2. 验收已实现的真实适配器：账户及可用持仓读取、委托/成交回报、撤单、断线重连、未知结果查询与恢复；`order_remark`仅作关联，不能当作券商幂等保证。接口代码已通过假SDK测试，真实终端尚未验收。
3. 建立独立券商对账与公司行动处理，完善交易时段、实时行情、盘口/竞价、真实成本和订单状态机。
4. 在券商测试环境验证超时、断网、重复回调、部分成交、拒单、撤单失败及故障恢复，再持续模拟观察。
5. 独立执行服务权限隔离、凭据保护、人工紧急停止和监控到位；用户另行明确手动授权真实交易范围。

CLI与自动引擎仍只允许模拟交易及QMT只读查询；独立实时API需要完整实时风控和额外短期人工授权，**不是改一个开关就能实盘**。未连接券商终端、未试真实下单。
